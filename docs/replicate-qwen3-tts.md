# Replicate Qwen3-TTS voice cloning

Voice Vault uses the verified `qwen/qwen3-tts` model version `d490a561cf1171a8dc3d96d1e57efffea7dd34607148bb641f3d9de4e38c472e` (the 1.7B Base voice cloning model). Each generation sends `mode=voice_clone`, a reference containing complete phrases from the user's recording, the transcript of that exact clip, and the configured language. No stock speaker or style instruction is sent.

Set `REPLICATE_API_TOKEN`, `REPLICATE_WEBHOOK_KEY`, and `VOICE_PROVIDER=replicate` in `.env`. The web and Celery worker both read `.env`. The worker needs `ffmpeg` to create a mono WAV reference. A voice reference is prepared when a Premium user with voice cloning consent chooses Clone Voice. The app stores the reference in its recordings storage and saves its path and matching transcript in `AIConfiguration`; preparing it does not call Replicate. The recording is sent to Replicate only when the user requests a voice preview or chat speech.

The processing page has a **Generate voice preview** action. Clicking it starts a paid prediction; repeating the same prepared text for the same reference and synthesis profile reuses the existing preview, including failed submissions whose outcome may be uncertain. The resulting audio is kept in Voice Vault storage and served to the owner through an authenticated endpoint. Chat responses use the same reference and store the prediction ID on the conversation to prevent automatic resubmission after a timeout. Provider charges are not reported as zero in usage records: `cost_usd` is left unknown because the prediction response does not return a billed amount. Check the Replicate dashboard for the actual charge.

## Reference preparation and natural phrasing

Reference preparation transcribes at most the first 60 seconds of the selected recording with Whisper word timestamps. It selects a continuous run of complete sentences lasting 3–20 seconds, preferring at least 8 seconds, multiple sentences and natural gaps. It preserves pauses within the crop and adds a small boundary margin without including adjacent words. The exact final crop is transcribed again before saving its audio/text pair. Preparing a reference therefore makes two bounded OpenAI transcription calls, and no Replicate synthesis call. If no usable complete phrase is found, preparation reports an actionable error and leaves the previous saved voice intact instead of cutting a sentence at 20 seconds. This selection does not measure emotional expressiveness or speaker similarity.

Chat prompts request short, naturally punctuated clauses and plain text. Chat speech and previews share a text preparation function that removes common Markdown formatting, preserves wording and existing punctuation, and punctuates paragraph/list boundaries. Soft line wrapping stays within the same sentence. Original chat text is retained for display. The app does not insert silence every few words, change playback speed, or send unsupported style/SSML controls to Base cloning.

`REPLICATE_LANGUAGE` defaults to `auto`; set it to `English` for an English-only deployment. Keep `auto` if replies use different supported languages. Set the same value on the web and voice worker. No language is guessed from Latin characters, which could also be another language or transliteration.

Chat cache and preview identities include the reference identity, Qwen version, language and speech-text revision. A changed profile does not reuse a previous profile's audio. Queued previews from older settings are rejected before submission; already-submitted predictions can still finish without another paid POST.

After deploying these changes, rebuild/restart the backend and voice worker together. Use **Clone Voice** again for existing accounts to prepare a reference with complete phrases, then request a new voice preview. There is no automatic migration, re-cloning or paid generation for existing users. Existing conversation audio remains its historical recording; new reference preparation and fresh replies are needed to hear the new behavior. No database schema migration is required for these changes.

Local use polls prediction status and needs no public callback URL. On a public deployment, set `REPLICATE_WEBHOOK_URL` to the externally reachable `https://<backend-host>/api/chat/replicate/webhook/`. The callback checks the `REPLICATE_WEBHOOK_KEY` signature and then retrieves the prediction through the API. The signing key is not the callback URL. Restart and rebuild both web and worker after changing configuration. Apply Django migrations before starting the app.

No generation request is made by setup or migration. The first preview or chat voice response is the user's live quality test. Voice similarity depends on the recording and model; an exact, accent-free match cannot be guaranteed by this integration.
